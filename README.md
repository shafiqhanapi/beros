# BEROS Crew Portal

Mobile-first web app where BEROS crew log monthly timesheet hours and claims, and the admin approves them before payout. The full product spec and database SQL are in [SPEC.md](SPEC.md).

Stack: Next.js (App Router, TypeScript) + Tailwind CSS, Supabase (Auth, Postgres, Storage), hosted on Vercel at https://crew.beros.online.

## Local development

```bash
cp .env.example .env.local   # fill in your Supabase URL and anon key
npm install
npm run dev
```

## Routes and guards

| Area | Paths | Who |
| --- | --- | --- |
| Public | `/login`, `/auth/callback`, `/auth/signout` | Anyone |
| Public | `/forgot-password`, `/forgot-password/sent` | Anyone |
| Signed in | `/reset-password` (reached from the reset email) | Any signed-in user |
| Crew | `/home`, `/timesheet`, `/claims`, `/history`, `/payslips`, `/profile` (+ `/phone`, `/paynow`) | `crew.role = 'crew'`, status not `inactive` |
| Admin | `/admin/*` | `crew.role = 'admin'` and `status = 'active'` (same as `is_admin()`) |

- `src/middleware.ts` refreshes the Supabase session and sends signed-out visitors to `/login`.
- `src/lib/auth.ts` loads the signed-in user's `crew` row; the `(crew)` and `admin` layouts enforce the role.
- `/` redirects to the right area; users without a crew row, or deactivated ones, see `/no-access`.
- Row-level security in Supabase is the real boundary; the guards keep the UI in step with it.

## Supabase setup (once)

1. In the SQL editor, run the blocks from SPEC.md → "Supabase setup" in order: services/add-ons/bookings, the main crew script, booking assignments, then the policies block.
2. Authentication → Providers: enable Email and Google. Turn off open sign-ups.
3. Authentication → URL Configuration: Site URL `https://crew.beros.online`; add `https://crew.beros.online/auth/callback` (and `http://localhost:3000/auth/callback` for local dev) to Redirect URLs.
4. Sign up once with your own email, then make yourself admin:
   `update crew set role = 'admin', status = 'active' where email = '<your email>';`

## Crew app (Phase 2)

Screens follow the Figma file "BEROS Crew Timesheet" (mobile frames 01–07b, desktop CD1–CD6).

- **Data**: `src/lib/data.ts` (reads) and `src/app/(crew)/actions.ts` (server actions) use the signed-in user's Supabase client, so RLS decides what each crew member can see and change.
- **Timesheet**: one per month. "To log" comes from the `my_bookings_to_log` view for that month; the booking name comes from `booking_items.item_label` (text before " · "). Entries copy the crew member's current `hourly_rate`.
- **Claims**: receipts upload from the browser to `receipts/<crew id>/<uuid>.<ext>` in the private bucket.
- **Payslips**: `/payslips/<payout id>/pdf` redirects to a 60-second signed link for `payouts.payslip_path` (the PDF is generated by the admin's "Mark as paid" in Phase 3).
- **Profile**: phone and PayNow are saved with `update_my_contact()`. The email-notifications toggle is stored in the auth user's `user_metadata.email_notifications`, as the `crew` table has no column for it.
- **Keep me signed in**: unticked sets a browser-session marker cookie; the middleware signs the user out once the browser has been closed.
- Emails (timesheet submitted, claim submitted, PayNow changed) are Phase 4 and marked `TODO(Phase 4)` in the actions.
